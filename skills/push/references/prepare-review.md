# Shared push stage

Used by `/push` and by `/ship` when work needs preparing. Reading this checklist from `/ship` is part of that explicit command, not automatic invocation of a separate user-only skill.

1. **Establish the target.** Read project instructions, status, changes and task scope. Discover origin's default branch. Stop on protected branches. For a verified linked native worktree without a branch, run `{{WG_HELPERS}}/worktree-start <unique-feature-branch> --adopt` to name it without losing changes. Never adopt a detached primary checkout.
2. **Check GitHub and review state.** Require authenticated `gh` for the origin host. Run `{{WG_HELPERS}}/workflow-status` from the feature workspace. Errors do not mean a missing PR. Stop on CLOSED. On MERGED, report whether later work exists; do not reopen or silently reuse the completed review. Select origin explicitly; refuse unfamiliar remotes/forks instead of guessing.
3. **Review intended work.** Inspect staged, unstaged, untracked changes and the full feature diff against the remote base. Include only this task. Read changed functions and callers. Check requirements/plan completion, correctness, failure handling, secrets, security implications and regression coverage. Fix only authorized issues; stop for unresolved blocking findings or user decisions. Run applicable documented tests, lint, type checks and builds. Report missing checks honestly; do not invent coverage, install a test framework, or waive a failing required check.
4. **Save before updating.** Commit selected work with clear messages. Follow project version/changelog conventions when required. If unrelated unsaved files prevent a clean update, stop and preserve them. No blanket staging, implicit stashing, or force push.
5. **Update and recheck.** Fetch origin; merge the open PR's fetched base, or remote default for a new PR. Resolve only conflicts within authorized scope; stop for logic conflicts requiring a decision. Review the resulting diff and run required checks on the resulting exact commit. Save any further fixes and rerun affected checks. Record tested commit and results.
6. **Publish review.** Confirm no unexpected changes arrived after testing. Push explicitly to `origin HEAD:refs/heads/<feature-branch>` and set its upstream to that feature branch. Never push directly to the default branch. Create the missing PR or update the existing open one using the project template, describing the problem, resulting behavior, verification and limitations. Use a body file or structured API for multiline text. A failed push stops PR creation.
7. **Find preview evidence.** Read PR checks/deployment metadata or query the configured provider using official tools. Return an actual URL tied to this change, never a guessed branch-derived URL. Explain preview coverage and pending/missing results. No deployment integration means no preview requirement.

Failed required checks or unresolved blocking findings stop publishing. This stage never merges or deletes branches. Success means a saved, tested, uploaded feature head and an open review.
